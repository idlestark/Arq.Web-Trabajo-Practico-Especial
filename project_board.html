Key Problem & Mitigation Report

MOB-108: Inter-Service Security Coupling & Feign Bean Collision

Managed by Lead Technical Project Manager • Phase 2 Delivery Hardening

1. The Problem (What went wrong?)

During end-to-end integration testing, inter-service communication ground to a halt. Two simultaneous issues emerged:

  • Security Coupling: Inherited global Spring Security dependencies caused internal backend services to block Feign requests with unexpected 401 Unauthorized challenges.
  • Bean Collision: Multiple Feign clients targeting the same remote microservice (Ticket & Fee) collided on duplicate Spring Bean specifications.

2. Business & Project Impact

This was a critical path blocker: the Admin microservice could not adjust tariffs or calculate fleet revenue, threatening our scheduled sprint delivery deadline.

3. PM Decision & Action Plan

  • Architecture Alignment: Enforced a clean perimeter security boundary: authentication is exclusively validated at the API Gateway; internal microservices are decoupled to accept routed calls without secondary authentication barriers.
  • Specification Hardening: Mandated unique contextId configurations for all OpenFeign clients and enabled explicit bean overriding policies.
  • Process Improvement: Added automated contract verification tests to our Definition of Done to catch schema mismatches before merging.

4. Result & Metrics

✓ 100% of inter-service calls restored with zero latency penalty.
✓ Critical sprint delivery completed on schedule without slipping milestones.
✓ Verified live in Postman with sub-second end-to-end response times.
